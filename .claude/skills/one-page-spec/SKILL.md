# One-Page Spec — 아이디어 → 즉시 개발 가능한 한국어 기획서

## 스킬 목적

사용자가 만들고 싶은 아이디어를 자유롭게 던지면, AI가 **컨설턴트 역할**로 핵심 3가지 질문을 던지고, 그 답을 바탕으로 **한국어 기획서 초안**을 만든다. 사용자가 **"끝"** 이라고 말하면 AI는:

1. 매력적인 서비스 이름을 창작하고 (기본 한글, 영문도 가능)
2. 완성된 한국어 One-Page Spec을 출력하고
3. `spec/[project-name].md` 파일로 저장한다

이 산출물은 그대로 다음 단계 코딩 프롬프트로 쓸 수 있다.

---

## 워크플로우 (5단계)

### Step 1 — 아이디어 수신

- 사용자가 인자(args) 없이 스킬을 호출한 경우: `"어떤 걸 만들고 싶으세요? 자유롭게 말씀해주세요 — 분위기나 떠오르는 디테일도 같이 좋아요."` 라고 한 줄로 묻고 기다린다.
- 사용자가 인자에 아이디어를 같이 넘긴 경우(예: `/one-page-spec 로또 번호 생성기, 카드 뒤집기 애니메이션`): 바로 Step 2로 진행.

### Step 2 — 핵심 3가지 질문 (한 번에)

**한 번의 `AskUserQuestion` 호출**에 **최대 3개 질문**을 담는다. 각 질문은 **2~3개 옵션**으로 구성한다 (사용자가 직접 입력하고 싶으면 자동 제공되는 "Other" 옵션을 사용).

질문은 아이디어 성격에 맞춰 동적으로 생성한다. 아래 카테고리에서 가장 결정적인 3개를 고른다:

| 카테고리 | 옵션 예시 |
|----------|-----------|
| **디자인 분위기** | A. 미니멀 애플 스타일 / B. 화려한 게임 스타일 / C. 따뜻한 종이감 |
| **데이터 저장** | A. Supabase DB에 저장 / B. 브라우저(localStorage)에 저장 / C. 저장 없이 일회용 |
| **핵심 인터랙션** | A. 카드 뒤집기 애니메이션 / B. 즉시 결과 표시 / C. 단계별 입력 폼 |
| **타겟 사용자** | A. 본인용 토이 / B. 친구끼리 공유 / C. 일반 대중 |
| **출력 형태** | A. 단일 HTML 페이지 / B. 모바일 반응형 / C. 데스크탑 전용 |
| **콘텐츠 양** | A. 한 화면 안에서 모두 / B. 여러 화면/탭으로 나누기 |

> 질문 선정 팁: 아이디어가 "메모장"처럼 명확하면 디자인+저장+인터랙션 중심으로, "게임"이면 분위기+인터랙션+타겟 중심으로 고른다.

질문 예시 호출 형태:

```json
{
  "questions": [
    {
      "question": "디자인 분위기는 어떤 게 좋을까요?",
      "header": "디자인",
      "multiSelect": false,
      "options": [
        {"label": "미니멀 애플 스타일", "description": "깔끔, 둥근 모서리, 여백 강조"},
        {"label": "화려한 게임 스타일", "description": "비비드 컬러, 그라데이션, 효과음 느낌"},
        {"label": "따뜻한 종이감", "description": "노란 포스트잇, 손글씨 폰트"}
      ]
    },
    {
      "question": "데이터는 어떻게 저장할까요?",
      "header": "저장",
      "multiSelect": false,
      "options": [
        {"label": "Supabase에 저장", "description": "기본값 — 인증/공유/동기화 가능"},
        {"label": "브라우저에 저장", "description": "localStorage — 새로고침해도 남음, 기기 종속"},
        {"label": "저장 없이 일회용", "description": "끄면 사라짐 — 가볍고 빠름"}
      ]
    },
    {
      "question": "핵심 인터랙션은 무엇인가요?",
      "header": "인터랙션",
      "multiSelect": false,
      "options": [
        {"label": "카드 뒤집기 애니메이션", "description": "결과를 카드 플립으로 공개"},
        {"label": "즉시 결과 표시", "description": "버튼 누르면 바로 결과"},
        {"label": "단계별 입력", "description": "마법사 형식으로 한 단계씩"}
      ]
    }
  ]
}
```

### Step 3 — 한국어 기획서 초안 출력

사용자 답을 바탕으로 한국어로 정리해서 보여준다. 형식:

```
📋 기획서 초안

1. 컨셉: { 한 줄 설명 }
2. 주요 기능: { 1~3개 }
3. 디자인: { 스타일 + 색상 톤 }
4. 기술 스택 (추천): { AI가 아이디어에 맞춰 추천 }
5. 데이터 구조: { 핵심 필드 1~3개 }

수정할 부분이 있으면 알려주세요. 마음에 들면 "끝"이라고 말씀해주세요.
```

### Step 4 — 조율 루프

사용자가 수정 요청(예: "색을 파스텔 톤으로", "기능 하나 더 추가") 하면 해당 부분만 다듬어 재출력. **사용자가 "끝"이라고 말하기 전까지 절대 Step 5로 넘어가지 않는다.**

### Step 5 — "끝" 감지 시 최종 출력

사용자가 "끝", "끝!", "끝이야", "완료" 등 종료 의사를 표현하면:

**(a) 매력적인 서비스 이름 창작**
- 컨셉이 잘 드러나는 이름. 기본은 한글, 어울리면 영문도 OK.
- 예: `로또플립`, `포근메모`, `오늘의운세 카드`, `LuckyFlip`, `Mellow Memo`
- 짧고 부르기 쉽게.

**(b) 완성된 한국어 One-Page Spec 출력** — 아래 템플릿 따라

**(c) 파일 저장**
- 경로: `spec/[name-kebab-case].md` (현재 작업 디렉토리 기준)
- 파일명은 영문 kebab-case로 변환 (예: `로또플립` → `lotto-flip.md`, `포근메모` → `pogeun-memo.md`)
- `spec/` 폴더가 없으면 `mkdir -p spec` 으로 생성
- 파일 내용은 한국어 Spec 그대로
- 저장 후 파일 경로를 한 줄로 안내

## 한국어 One-Page Spec 템플릿

저장 파일과 출력 모두 이 형식을 따른다:

```markdown
# [AI가 지은 서비스 이름] — One-Page 기획서

## 1. 컨셉 (한 줄 정의)
{ 이 서비스가 무엇을 하는지 명확한 한 문장 }

## 2. 기술 스택
- **프레임워크**: { 기본: Next.js (App Router) + Tailwind CSS + TypeScript }
- **데이터 저장**: { 기본: Supabase (Postgres + Auth). 필요 시 localStorage / 저장 없음 }
- **에셋**: { 예: Lucide React 아이콘, Google Fonts (Noto Sans KR) }

## 3. 핵심 기능 (최대 3개)
1. { 가장 중요한 기능 }
2. { 두 번째 기능 }
3. { 세 번째 기능 — 없으면 생략 }

## 4. 디자인 컨셉 (Look & Feel)
- **스타일**: { 예: 미니멀 애플 스타일, 모서리 12px 둥글게 }
- **컬러**: { 메인 #FF5733, 배경 #F0F0F0, 포인트 #2D2D2D }
- **모션**: { 예: 카드 플립 애니메이션 0.6초 ease-out }

## 5. 데이터 구조
\`\`\`json
{
  "key": "value"
}
\`\`\`
```

## 기술 스택 추천 가이드 (AI 내부 휴리스틱)

기본 스택은 항상 **Next.js (App Router) + Tailwind CSS + Supabase + TypeScript**. 처음부터 인증·DB·배포까지 갖춘 풀스택 구조로 시작한다.

아이디어 성격에 따라 추가 라이브러리만 얹는다:

| 아이디어 성격 | 추가/조정 |
|---------------|----------|
| 단순 단일 페이지 도구 (메모, 계산기, 추첨기) | 기본 스택 그대로. Supabase는 익명 세션으로 |
| 저장 필요한 개인용 도구 | 기본 스택 + Supabase Auth (이메일 또는 OAuth) |
| 공유/멀티유저 | 기본 스택 + Supabase Realtime |
| 인터랙티브 애니메이션 중심 | 기본 스택 + Framer Motion |
| 3D / 게임 | 기본 스택 + React Three Fiber 또는 Phaser |
| 진짜로 저장 불필요한 일회용 | 기본 스택, Supabase 연동 생략 (사용자 선택 시) |

**기본은 항상 Next.js + Tailwind + Supabase** — 토이라도 배포·확장까지 한 흐름으로 갈 수 있도록 기본을 풀스택으로 잡는다.

## 진행 규칙 (절대 위반 금지)

1. **한 번에 최대 3개 질문**, 각 질문은 **2~3개 옵션** (AskUserQuestion이 "Other"를 자동 추가).
2. 사용자가 **"끝"** 이라고 말하기 전까지 작명, 파일 저장을 **절대 하지 않는다**.
3. **기획서는 항상 한국어로만 출력한다.** 영문 번역은 하지 않는다.
4. 파일명은 **영문 kebab-case** (`lucky-flip.md`, `pogeun-memo.md`). 한글 파일명은 사용하지 않는다.
5. 파일 저장 위치는 **현재 작업 디렉토리의 `spec/` 폴더**. 폴더가 없으면 `mkdir -p spec`으로 만든다.
6. 질문 카테고리는 아이디어에 맞춰 **동적으로 선택**한다. 매번 같은 3개를 묻지 않는다.

## 시작

스킬이 호출되면:
- 인자에 아이디어가 있으면 → **Step 2 (질문)** 부터 시작
- 인자가 비었으면 → **Step 1 (아이디어 묻기)** 부터 시작
